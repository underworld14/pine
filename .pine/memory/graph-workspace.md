# graph-workspace

- 2026-08-05: Typed links field connects tickets/memory/learnings; backlinks are computed. Multi-repo serve auto-discovers repos from `~/.pine/repos.json` (auto-populated by `pine init` — no `pine workspace` command, no `--workspace` flag) via StoreRegistry, `/api/r/{alias}/*`, and repo-tagged SSE. `--only` restricts serve to the cwd repo.
- 2026-08-05 (code-review round 2): When adding per-repo/per-tenant routing to an existing server, audit EVERY handler — alias routes that fall back to the active/default store silently mutate the WRONG repo (data corruption). Pattern: `st := srv.storeOf(r)` at the top of each handler; guard active-only side effects (reindex/kickCrossBranch/offBranchRef) with `if st == srv.store`; tag SSE with `srv.registry.AliasOf(st)`. Add PUT/PATCH/DELETE-via-alias tests — the working routes (GET/POST) give false confidence.
- 2026-08-05 (code-review round 2): A server that swaps fields on a "switch active" call (`SetActiveRepo` reassigns store/git/search/cross-branch caches) races with its own pollers/watchers. Guard each swapped field with its own RWMutex (`storeMu`/`gitMu`/`crossMu`/`searchMu`), expose locked accessors (`activeStore()`/`gitClient()`/`searchIdx()`), and add a `-race` test that hammers SetActiveRepo while pollers tick and handlers read. Don't replace the cross-branch kick channel — create it once and snapshot it in the poller.
- 2026-08-05 (code-review round 3): Caching a derived graph on a Store invites a lock-ordering inversion: the cache accessor takes `cacheMu` then calls `s.All()` (which takes `s.mu`), while write paths hold `s.mu` then invalidate the cache (take `cacheMu`) → `s.mu→cacheMu` vs `cacheMu→s.mu`. Build the cached value OUTSIDE the cache lock (snapshot inputs under their own locks), then store under the cache lock; invalidation takes only the cache lock. That makes the order consistently `s.mu→cacheMu` with no cycle.
- 2026-08-05 (code-review round 3): A file watcher that only knows tickets/config/learnings leaves memory-topic edits invisible to a long-running server. Adding a `KindMemory` (classify `memory/*.md` + `MEMORY.md`) and invalidating the derived-graph cache on it keeps the unified graph coherent without a new SSE event (the graph view polls/refetches on demand).
- 2026-08-05 (code-review round 3): A single "active-repo" poller can't give live updates for non-active repos. Run one poller per registered repo, each emitting a repo-tagged event; the active repo's poller also updates the shared active-store cache. On the client, cache per-repo state (`gitByRepo`) BEFORE the per-repo SSE filter drops non-active events, and promote the active repo's entry to the displayed field — switching repos is then instant. Make the poll interval injectable so a race test can drive a tick fast.
- 2026-08-05: Caching a derived value with double-checked locking still leaks stale data when a writer can invalidate mid-build: the builder snapshotted inputs at gen=N, a writer bumped gen to N+1 and niled the cache, then the builder stored its N-input result — serving stale. Fix: snapshot the generation before building, and under the cache write-lock re-check the generation; if it changed, discard the build and rebuild. The invalidation path bumps the generation under the same lock.
- 2026-08-05: A background poller that initializes its baseline (prev) inside the goroutine races with a test/user committing immediately after start: if the goroutine hasn't snapshotted yet, the commit becomes the baseline and no change-event fires (flake). Fix: take the baseline snapshot synchronously before spawning the loop, so 'started' implies 'armed'. Snapshots are fast/bounded; doing them sequentially at startup is cheaper and more correct than a fixed 'sleep before the test commit'.
